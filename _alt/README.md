# ORA-cle

Browser app for viewing GO enrichment results (lollipop / dot plots, filters, manual and semantic clustering,
gene matrix, PNG / CSV export). It is a **static site**: plain ES modules, no bundler, no Node build step.
D3 7.8.5 is loaded from its CDN `<script>` tag and stays a global `d3`. Rendering is SVG.

## Run it locally

Modules and `fetch` need `http://`, not `file://`:

    python3 -m http.server 8000      # from this folder
    # open http://localhost:8000/

GitHub Pages: publish the repository root. The `data/` folder is found relative to `js/go/data.js`, so it works
under a sub-path such as `https://user.github.io/repo/`.

## Layout

    index.html            markup only; d3 CDN script; <script type="module" src="js/main.js">
    css/                  stylesheet split by area (loaded in this order, same order as the old single <style>)
    js/main.js            startup and wiring
    js/state.js           shared state (`state`, `controls`, palettes, defaults)
    js/utils.js           small DOM / number helpers
    js/io/                parse.js, formats/{native,gprofiler,genecodis}.js, hash.js, upload.js, examples.js
    js/panels.js          panel management
    js/pipeline.js        getPanelData (filter, sort, slice, cluster order)
    js/plot/              render.js, title-edit.js, gene-matrix.js, sticky.js
    js/clustering/        manual.js, manual-ui.js, semantic/{wang,ic,linkage,matrix,run}.js
    js/go/                data.js (fetch manifest, graph, definitions, IC), tooltip.js
    js/ui/                actions.js (delegated events), sidebar.js, header.js, export.js, organism.js, info-tip.js
    data/                 GENERATED by tools/build_data.py (committed so the site works without a build)
    tools/build_data.py   builds data/
    tests/                Node / Python checks

DOM-free at import time (importable from Node): `io/parse.js`, `io/formats/*`, `pipeline.js`, `state.js`,
`clustering/manual.js`, `clustering/semantic/{wang,ic,linkage,matrix}.js`, `go/data.js`.

## UI events

There are no inline `onclick=` handlers. Markup uses `data-on-click`, `data-on-input`, `data-on-change`, `data-on-blur`
with an action name (plus `data-*` arguments). `js/ui/actions.js` holds the action table and the single delegated
listener. To add a control: add the attribute in `index.html`, add one line to `actions`.

## Rebuild the data

    python3 tools/build_data.py --obo go-basic.obo --ic-dir <folder with the *_IC.csv files> --out data

Needs only the Python standard library. Graph and definitions come from `go-basic.obo` only. Edge weights
(is_a 0.8, part_of 0.6, other 0.7) are constants at the top of the script. The build **fails** on a cycle, on a
definition without a graph term, or on an empty BP / MF / CC; it **warns with counts** about IC terms that are not in
the graph (dropped) and graph terms without IC, and prints a summary table. The GO release shown in the app is the
OBO's `data-version` (override with `--go-release`).

## Add an organism

1. Put `<id>_IC.csv` (columns `term_id,ic`) in the IC folder.
2. Add one row to `ORGANISMS` at the top of `tools/build_data.py` (id, label, species, taxon, orgdb package, version).
3. Rerun the build. The dropdown is filled from `data/manifest.json`; nothing else changes.

    node tests/verify-old-graph.mjs <old index.html> tests/samples/clusters-13-49terms.csv   # needs ORIGINAL file + acorn
